# VR-0001, Connection, scene and tick hold

> **Navigation**: [Verification](./README.md)

**Phase 0 experiments.** 1 and 2.

**Purpose.** Establish that a client reaches the kRPC server, what the server reports,
and whether the tick hold steps the game one physics tick at a time.

**Configuration.** Kerbal Space Program 1.12.5 with both expansions, kRPC 0.7.0 server
and Python client, on an arm64 Mac under macOS 27.2.1. Save "Ikria Simulated Research and
Dev", a sandbox on Hard. Probe scripts are in [`tools/phase0/`](../../tools/phase0/README.md),
in their final versions, and raw outputs in [`data/`](data/). Runs took place on
2026-11-14, in Coordinated Universal Time.

**Procedure.**
1. `probe_connect.py` connected with the save loaded at the Space Center, read the server
   version, scene, mode and game time, and timed 200 sequential reads of game time.
2. `probe_inventory_tick.py` held the tick, stepped it 50 times with `next_tick`,
   reading game time after each step, and released the hold in a `finally` block.

**Results.**
- At the main menu nothing listened on ports 50000 and 50001, and the connection was
  refused. Once a save was loaded the client connected. Server 0.7.0, scene
  `space_center`, mode `sandbox`.
- A sequential read of game time took 0.256 ms on average at the Space Center.
- Each `next_tick` advanced game time by exactly 0.02 s, so the fixed update is 50 per
  second. The 50 held cycles took 994.2 ms of wall time, 19.88 ms each.

**Deviations.** None.

**Conclusions.** Lockstep at one step per tick is possible through the tick hold, and
runs at about real-time pace. The fixed update is 50 per second, not the 60 that
kRPC's documentation gives.
