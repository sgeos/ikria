## Manual placement and armed continuation

After both timed-out requests had ended, accepting the warning alone did not produce
an article in subsequent snapshots. The operator then placed the empty article through
the editor and reported it on the pad. An independent guarded observation confirmed
PreLaunch, zero crew, eight parts, 35 solid-fuel units, an inactive motor and a stowed
parachute. This demonstrates the manual workaround once. I-0008 remains open for
placement reliability and the unverified automated alternative.

The continuation used Ikria main `7907697` and the unchanged bridge `ef85dd8`, with
the harness rebuilt. All four kerbals were Available and the career hash was unchanged.
The editor changed the craft's root version and description fields. Comparing against
the original derivation found no part-configuration change. This is a documented
exception to TP-0003's original whole-file hash requirement. The bridge checked the
same physical profile before every armed session. The new checkpoint is
`ipv-flight-fix-manual-pad-20261122`.

The default pad abort completed without ignition. The refused-pad fixture produced
an invalid phase transition from 0 to 2 at sequence zero. The distinct abort program
answered that same sample with a neutral completion command, which was acknowledged.
Neither pad check issued a discrete action. Both journals replayed exactly.

The normal hop issued one ignition at sequence zero and one parachute deployment at
sequence 1114. It reached 1,241.222 m. After 3,558 samples and acknowledgements over
71.14 game seconds, the bridge exited with `Elapsed(())`. The harness recorded a
failed terminal event with `message codec: truncated or oversized frame`. The last
acknowledged sample was descending at 410.842 m, with eight parts and the chute deployed.
No completion event was recorded.

The bridge's completed handshake and approximately 149 seconds of wall time identify
its 700 ms cycle deadline as the timeout source by source-code inference. The current
diagnostics do not identify which operation stalled. A codec error after the bridge
disconnect does not establish that an oversized frame was received. The next logged
autosave was after the failure, so no autosave cause is established. I-0009 records
the failure and the required diagnostic work.

No further control was sent after disconnection. Independent observations found the
article descending under its parachute, then landed. Six observations spanning 4.46
game seconds all showed Landed, eight parts, zero crew and vertical speed below
0.001 m/s in magnitude. The article was recovered. These observations establish a
passive recovery, not a successful harness flight or an exact touchdown time.

## Tools and verification

`run_flight.py --program-body` passes a chosen normal body to the existing `fly`
interface. The deliberately faulty bodies are under `programs/verification/` and must
not be used for a nominal flight. A regression test loads those exact files, checks
pad inhibition, same-sample boost takeover and a completed simulated descent.

`setup_early_hop.py place --uncrewed` adds explicit empty-crew placement, a 180-second
operator-response window, a logged launch intent and checks for the returned craft,
crew count, PreLaunch state and inactive motor. Its postconditions have negative tests.
The live diagnostic calls preceded this integrated option, so the option itself has
not completed a live placement. It is not a demonstrated cure for the warning.

The full local gate passes with 158 Rust tests, 51 Phase 0 Python tests and 12 gate
tests, none ignored, on macOS. The unchanged bridge's gate passed with three Rust tests
and its gate tests. Pull-request checks record remote validation after publication.
