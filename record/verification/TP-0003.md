# TP-0003, Flight-Control Fix Verification

> **Navigation**: [Verification](README.md) | [Report VR-0012](VR-0012.md)

**Date and author.** 2026-11-22, Codex.
**Scope.** Development verification in Ikria Physical Verification, with no career clearance.

## Objective

Exercise the corrected harness against the live bridge and game. Establish that a
refused normal output selects the distinct abort program on the same sample, that the
refused command is not sent, and that the abort path can finish a hop and recovery.
Observe ordinary operation with the new frame and session deadlines. This does not
replace offline fault tests for malformed transport or delayed telemetry.

## Preparation and constraints

Identify the loaded save through the guarded temporary snapshot. Require all four
kerbals Available and no crewed vessel near either launch site. Retain the career and
craft hashes and debug flags. Checkpoint the verification save before placement.
Use the existing eight-part IKR-TS-001B with 35 units of solid fuel and a 20 percent
thrust limit. Compare the craft hash with VR-0010. If an editor save changes it,
stop until a documented comparison identifies every changed field. A metadata-only
change to root version or description can be admitted with unchanged part configuration
and a fresh successful bridge profile check. Retain both hashes. No debug setter is planned.

Rebuild both executables from the recorded revisions. Use the R20 launch-site helper
before every placement. Place with the motor off, remove and recover the kerbal,
then verify zero crew and select the empty article. Also require PreLaunch before
arming. If crew removal changes it to Landed, stop preparation. An alternative is
`setup_early_hop.py place --uncrewed`, with the operator handling the No Control warning
while the request remains active. VR-0012 has not yet verified this alternative. Never retry an uncertain outcome.
Manual editor placement is a demonstrated alternative from VR-0012, with crew
explicitly empty and the motor off. Inspect its actual PreLaunch state before arming.
If placement or crew removal fails, inspect and secure the crew before proceeding.
Keep the measured vessel active and announce each run before starting it.

## Runs and acceptance criteria

| Run | Inputs | Required observation |
|---|---|---|
| Monitor | Default source, 50 ticks | No discrete command, all acknowledgements, successful close |
| Pad abort | Default sources, pad-abort mode | No ignition, successful aborted completion |
| Refused pad output | `programs/verification/refused-pad.kl` | Invalid phase transition is journalled, same-sample abort command acknowledged, no ignition |
| Normal hop | Default normal and abort sources, 12,000 ticks | One ignition and one deployment, settled touchdown, eight-part recovery |
| Refused boost output | `programs/verification/early-completion.kl`, 12,000 ticks | Completion while flying is refused above 20 m, distinct abort takes over during boost, one ignition and one deployment, settled touchdown and eight-part recovery |

The fault fixtures are explicit verification inputs. They do not modify telemetry or
weaken command policy. A new output directory and absent abort-request path are used
for each session. The boost fault changes only the normal program's phase output.
The independent abort source remains the bundled `programs/abort.kl`.

For every completed session, replay the journal with the recorded source pair. Inspect
fault events, same-sample command ordering, acknowledgement count, action counts,
source hashes, clock increments and final state. Recover each flight article before
placing another. Record the final roster, debug flags and career hash.

## Evidence and failure handling

Retain journals, diagnostics, setup and recovery records, hashes and summaries in
VR-0012's data directory. Preserve unsuccessful runs without certifying them by replay.
An unexpected loss or software failure receives an incident report. Transport loss
ends the session and does not guarantee recovery. Solid motors cannot be stopped.
No live malformed-frame injection or deliberate loss of transport is planned.
